# MCP Enterprise Operations Assistant

A modular learning project that demonstrates how to build an enterprise operations assistant using **Python, `uv`, the Model Context Protocol (MCP), Groq, and Streamlit**.

The assistant can query four simulated enterprise information domains:

1. **CRM** — customers and account managers
2. **HR** — employees and technical skills
3. **ITSM** — service tickets and incidents
4. **Knowledge** — company policies

The application uses synthetic JSON data so it can be run locally without connecting to real enterprise systems.

---

## 1. What this project demonstrates

- **MCP server:** exposes enterprise operations as tools and a resource.
- **MCP client:** discovers available tools and invokes them through MCP.
- **LLM tool calling:** uses a Groq-hosted model to select tools and formulate answers.
- **Streamlit UI:** provides a browser-based chat interface and displays the tool execution trace.
- **Modular Python design:** separates configuration, agent logic, MCP client/server, UI, data, and tests.
- **Explainability:** comments and the execution trace help learners understand the request flow.

> **Important:** MCP standardizes how an application exposes and calls tools. It does not provide the LLM's reasoning by itself, and it does not guarantee that a model's answer is correct.

## 2. Architecture and request flow

```text
User
  |
  v
Streamlit UI (app/streamlit_app.py)
  |
  v
Groq Agent (app/groq_agent.py)
  |  1. Sends user question and tool definitions to Groq
  |  2. Receives tool-call requests from the model
  v
MCP Client (app/mcp_client.py)
  |
  |  stdio transport
  v
MCP Server (app/mcp_server.py)
  |
  +--> CRM data       (data/customers.json)
  +--> HR data        (data/employees.json)
  +--> ITSM data      (data/tickets.json)
  +--> Policy data    (data/policies.json)
  |
  v
Tool results return to the agent, which asks the model to compose a response.
  |
  v
Streamlit displays the answer and tool execution trace.
```

The MCP server runs as a local subprocess over **stdio**. The Streamlit application does not directly query the JSON files; the tools exposed by the MCP server perform the data operations.

## 4. Prerequisites

Install the following before running the application:

- **Windows 10/11**
- **Visual Studio Code**
- **Python 3.12** (the project requests Python 3.12 or later)
- **uv** — Python package and project manager
- **A Groq API key** — needed for LLM responses
- Internet access when installing dependencies and calling the Groq API

You can obtain a Groq API key from: <https://console.groq.com/keys>

Do not put a real API key in source code or commit your `.env` file to Git.

## 5. Open the project in VS Code

1. Download and extract the project ZIP.
2. Open VS Code.
3. Select **File → Open Folder**.
4. Select the extracted `enterprise-operations-assistant` folder.
5. Select **Terminal → New Terminal**.

The terminal should be at the **project root**, where `pyproject.toml`, `app`, `data`, and `tests` are visible.

Verify the location:

```powershell
Get-Location
Get-ChildItem
```

If the terminal is not at the project root, change directory to the extracted folder. For example (replace the path with your actual location):

```powershell
Set-Location "D:\GenAI\enterprise-operations-assistant"
```

Do not run project commands from inside the `app` or `tests` folder.

## 6. Install and verify uv

Check whether `uv` is installed:

```powershell
uv --version
```

If PowerShell reports that `uv` is not recognized, install it using the official Windows installer:

```powershell
irm https://astral.sh/uv/install.ps1 | iex
```

Close and reopen the VS Code terminal, then verify:

```powershell
uv --version
```

Install Python 3.12 through `uv`:

```powershell
uv python install 3.12
```

Verify the Python version that `uv` will use for the project:

```powershell
uv run python --version
```

The project requires Python 3.12 or later. If `uv` selects a different compatible version, check the `requires-python` setting in `pyproject.toml`.

## 7. Install project dependencies

From the project root, run:

```powershell
uv sync
```

This creates or updates the project's virtual environment (normally `.venv`), installs the dependencies declared in `pyproject.toml`, and creates or updates `uv.lock`.

Verify the main packages:

```powershell
uv run python -c "import mcp, groq, streamlit; print('Dependencies imported successfully')"
```

If installation fails because of disk space, free disk space and rerun `uv sync`. If the virtual environment becomes inconsistent, you can recreate it from the project root:

```powershell
Remove-Item -Recurse -Force .venv
uv sync
```

Only remove `.venv` if you are comfortable reinstalling the project's dependencies. Do not remove your source files or `data` folder.

## 8. Configure the Groq API key

Create your local environment file by copying the example:

```powershell
Copy-Item .env.example .env
```

Open `.env` in VS Code and replace the placeholder with your actual Groq API key:

```dotenv
GROQ_API_KEY=your_actual_groq_api_key
GROQ_MODEL=openai/gpt-oss-120b
```

Use the exact model ID supported by your Groq account and the project's tool-calling implementation. If that model is unavailable, choose a currently available Groq model that supports tool calling and update `GROQ_MODEL`.

Check that the key is loaded **without printing the key itself**:

```powershell
uv run python -c "from app.config import GROQ_API_KEY; print('Groq API key loaded:', bool(GROQ_API_KEY))"
```

Expected result:

```text
Groq API key loaded: True
```

If it prints `False`, confirm that:
- `.env` is in the project root, alongside `pyproject.toml`.
- The variable is named `GROQ_API_KEY`.
- The key is not surrounded by unintended quotation marks or spaces.
- You restarted the command after editing `.env`.

## 9. Fix `ModuleNotFoundError: No module named 'app'`

If a command fails with:

```text
ModuleNotFoundError: No module named 'app'
```

Python is usually running without the project root on its import path, or the terminal is in the wrong directory.

### 9.1 Confirm the project root

```powershell
Get-Location
Get-ChildItem
```

You should see both `pyproject.toml` and the `app` directory.

### 9.2 Confirm the package file exists

```powershell
Test-Path .\app\__init__.py
```

Expected output:

```text
True
```

### 9.3 Set `PYTHONPATH` for the current PowerShell terminal

```powershell
$env:PYTHONPATH = (Get-Location).Path
```

This adds the current project root to Python's module search path for this terminal session.

### 9.4 Test the import

```powershell
uv run python -c "import app; print('App package imported successfully')"
```

Expected output:

```text
App package imported successfully
```

Set `PYTHONPATH` again whenever you open a new terminal. It is a session-level environment variable.

## 11. Start the Streamlit application

From the project root, run:

```powershell

```

Streamlit should display a local URL, usually:

```text

```

Open that address in your browser. Enter a question in the application and inspect the response and tool execution trace.

To stop the application, return to the terminal and press:

```text

```

If port 8501 is already in use, run the application on another port:

```powershell
uv run streamlit run app/streamlit_app.py --server.port 8502
```

Then open `http://localhost:8502`.

## 13. How to add or change sample data

The demo data is stored in the `data` directory:

- `customers.json`
- `employees.json`
- `tickets.json`
- `policies.json`

Before editing a file, inspect its existing structure and preserve the same JSON field names and data types. Keep the JSON syntactically valid. For example, use double quotes around JSON property names and string values.

After making changes, validate the data:

```powershell
uv run pytest -q tests/test_data.py
```

The MCP tools read the data using the project's implementation. If you introduce new fields or want to search on a field that is not currently supported, update the corresponding tool implementation in `app/mcp_server.py` as well.

## 14. Troubleshooting

| Symptom | Checks and suggested action |
|---|---|
| `uv` is not recognized | Install `uv`, reopen the VS Code terminal, and verify with `uv --version`. |
| `No module named 'app'` | Navigate to the project root, check `app/__init__.py`, and set `$env:PYTHONPATH = (Get-Location).Path`. |
| `No module named 'mcp'` | Run `uv sync`, then verify with `uv run python -c "import mcp"`. |
| `No module named 'groq'` | Run `uv sync`, then verify with `uv run python -c "import groq"`. |
| API key missing | Check that `.env` is in the root and contains `GROQ_API_KEY=...`. |
| Authentication or invalid API key error | Generate or verify your key in the Groq console; do not share the key in logs or chat. |
| Model not found or unavailable | Check the current model ID available to your account and update `GROQ_MODEL` in `.env`. The chosen model must support tool calling. |
| MCP connection or tool discovery fails | Run the MCP connection test from the project root and check the full traceback. Verify dependencies and `PYTHONPATH`. |
| Streamlit cannot import `app` | Set `PYTHONPATH` in the same terminal and launch Streamlit from the project root. |
| Port 8501 is occupied | Use `--server.port 8502` and open the new local URL. |
| JSON parsing error | Validate the edited JSON file and compare it with the original file's schema. |
| Disk space error during `uv sync` | Free disk space and retry. If necessary, recreate `.venv` as described in Section 7. |

For errors that persist, copy the **complete traceback**, the command you ran, and the output of `Get-Location`. Redact API keys and other secrets before sharing logs.
